SECTION 0  —  WHY v2 EXISTS — READ THIS FIRST
0. What Changed Since Stage2_Implementation_Guide_v1
v1 was built entirely on the district-level Kaggle factsheet (~707 districts, 115 percentage-indicator columns). PBC has since confirmed Stage 1 is rebuilt on the real individual-level DHS file (724,115 women, NFHS5_Individual.csv — a 32-column extract of IAIR7EFL.DTA), with real v467-based barrier targets at 27% / 32% / 46% prevalence. Every district-level assumption in v1 — OOF probabilities keyed to districts, clustering on district percentages, Stage 2 targets built from district-level NCD/cancer-screening/nutrition columns — no longer applies. This document rebuilds Stage 2 end-to-end on the individual-level data, following the same v1 structure so the team doesn't have to relearn conventions.
CONFIRMED WITH PBC — CARRIED FORWARD FROM STAGE 1 v5:
v467f and v467i are not present in the India NFHS-5 individual extract — Household and Facility barrier targets are built from b+c and g+h only, by design, not by omission. Analytic sample is the full 724,115 women (barrier module has zero missingness); the ~108K figure some columns show is structural (subset-only questions), not a filtering decision. Both carry through unchanged into every Stage 2 step below.
0.1 The One New Constraint This Guide Has to Work Around
v1 could reach into 115 district-level columns to build rich Stage 2 outcome targets (child nutrition, NCD burden, cancer screening, family planning uptake). The individual-level extract PBC is working from has only 32 columns, and only two of them are plausible, independent health-outcome measures: m14 (ANC visit count) and v626a (unmet need for family planning). Everything else in the extract is either already a Stage 1 feature/target, an identifier, or — in the case of s245a/s245b/s245h — conceptually the same thing as the barrier module (reasons a complication went untreated: cost, transport, permission), just for a different survey question. Section 2 below explains the call I'm making on this and why.

SECTION 3  —  STAGE 1 → STAGE 2 DATA INTEGRATION  [Owner: RBM]
3. Building the Stage 2 Feature Matrix
3.1 Why Out-of-Fold Predictions Still Matter — Now More Than Ever
Same leakage logic as v1 Section 3.1: Stage 1's models were trained on an 80% split, so calling .predict_proba() on the fitted models across all rows gives artificially confident scores for the ~579K training rows and honest scores for the ~145K test rows. At individual-level scale this gap would be even more consequential — it's a much larger fraction of a much larger dataset silently biased. cross_val_predict remains mandatory.
3.2 The Fix — OOF at 724K-Row Scale
# src/preprocessing/stage2_integration.py
from sklearn.model_selection import cross_val_predict, StratifiedKFold
from xgboost import XGBClassifier
import pandas as pd
def build_oof_barrier_probabilities(X, y_household, y_logistic, y_facility, n_splits=3, random_state=42):
'''3-fold instead of 5-fold by default — at 724K rows this halves OOF compute
time with negligible change in prediction stability. Bump to 5 if runtime allows.
Use the winning Stage 1 model per target once 06_stage1_model_compare.ipynb confirms it —
XGBoost with tree_method="hist" shown below as the default assumption.'''
kf = StratifiedKFold(n_splits=n_splits, shuffle=True, random_state=random_state)
base_kwargs = dict(max_depth=6, n_estimators=300, learning_rate=0.08,
subsample=0.8, colsample_bytree=0.8, tree_method='hist', random_state=42)
oof = {}
for name, y in [('household_barrier_prob', y_household),
('logistic_barrier_prob', y_logistic),
('facility_barrier_prob', y_facility)]:
neg, pos = (y == 0).sum(), (y == 1).sum()
model = XGBClassifier(scale_pos_weight=neg / pos, **base_kwargs)
oof[name] = cross_val_predict(model, X, y, cv=kf, method='predict_proba', n_jobs=-1)[:, 1]
return pd.DataFrame(oof)
COMPUTE NOTE:
3-fold XGBoost OOF across three ~724K-row targets is still a non-trivial job. Run it as a background/batch script rather than interactively in Jupyter, and checkpoint each target's OOF array to disk as it finishes (np.save) so a crash on target 3 doesn't lose targets 1-2.

SECTION 4  —  K-MEANS CLUSTERING — WOMAN-LEVEL RISK ARCHETYPES  [Owner: PBC]
4. Clustering at Individual-Woman Scale
4.1 What Changes From v1
Unit of clustering is now one woman, not one district — 724,115 points instead of 707. Plain KMeans' full-data Lloyd's-algorithm iterations become slow at this scale; use MiniBatchKMeans instead, which is designed for exactly this.
Silhouette scoring on the full 724,115 rows for every k in 2-10 is not necessary and would be slow — score silhouette on a fixed random stratified subsample (e.g. 20,000 rows), pick k from that, then fit the final MiniBatchKMeans on the full data.
The approach document's dashboard concept (state-level choropleth) now needs an aggregation step: woman-level cluster labels and barrier probabilities get grouped by v024 (state) — or a district identifier if the team later links in DHS spatial/district-linkage data — before they can populate a district or state map. That aggregation belongs in the BarrierLens platform notebook (13, still pending), not in this clustering step; noting it here so it isn't a surprise later.
4.2 Implementation
# src/clustering/kmeans_cluster.py
import pandas as pd, numpy as np
from sklearn.preprocessing import StandardScaler
from sklearn.cluster import MiniBatchKMeans
from sklearn.metrics import silhouette_score
import joblib
CLUSTER_FEATURES = [
'media_exposure_index', 'digital_inclusion_index', 'vulnerability_score',
'household_barrier_prob', 'logistic_barrier_prob', 'facility_barrier_prob',
]
def find_best_k(X_scaled, k_range=range(2, 11), sample_size=20000, random_state=42):
rng = np.random.RandomState(random_state)
idx = rng.choice(len(X_scaled), size=min(sample_size, len(X_scaled)), replace=False)
sample = X_scaled[idx]
scores = {}
for k in k_range:
labels = MiniBatchKMeans(n_clusters=k, random_state=random_state, n_init=10).fit_predict(sample)
scores[k] = silhouette_score(sample, labels)
print(f'k={k}: silhouette={scores[k]:.4f} (on {len(sample)}-row subsample)')
best_k = max(scores, key=scores.get)
print(f'Best k: {best_k} (silhouette={scores[best_k]:.4f})')
return best_k, scores
def fit_clusters(X_stage2):
X_cluster = X_stage2[CLUSTER_FEATURES]
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X_cluster)
best_k, scores = find_best_k(X_scaled)
model = MiniBatchKMeans(n_clusters=best_k, random_state=42, n_init=10, batch_size=4096)
labels = model.fit_predict(X_scaled)
joblib.dump(model, 'saved_models/stage2/kmeans_model.pkl')
joblib.dump(scaler, 'saved_models/stage2/kmeans_scaler.pkl')
return labels, model, scaler, X_cluster

6.2 Model 1 — Multi-Output Logistic Regression  [Owner: PBC]
MultiOutputClassifier requires a single shared row set across targets, which the two independent restricted samples above don't give. Train two separate LogisticRegression models instead (one per target, on its own restricted sample) rather than forcing a MultiOutputClassifier wrapper — simpler and avoids silently dropping rows that are valid for one target but not the other.
# src/models/stage2_logistic.py
from sklearn.linear_model import LogisticRegression
import joblib, numpy as np, pandas as pd
def train_stage2_logistic(X_train, y_train, feature_names, target_name):
model = LogisticRegression(solver='lbfgs', max_iter=1000, C=1.0,
class_weight='balanced', random_state=42)
model.fit(X_train, y_train)
joblib.dump(model, f'saved_models/stage2/stage2_logistic_{target_name}.pkl')
coefs = pd.DataFrame({'Feature': feature_names, 'Coefficient': model.coef_[0],
'OddsRatio': np.exp(model.coef_[0])}).sort_values('OddsRatio', ascending=False)
print(f'--- Top predictors for {target_name} ---'); print(coefs.head(10))
return model

SECTION 7  —  EVALUATION STRATEGY
7. Evaluation
7.1 Metrics — Framing Updated, Definitions Unchanged
Accuracy, ROC-AUC, Precision, Recall, F1, Confusion Matrix — same computation as Stage 1 v5's evaluation code (RBM's stage2_metrics.py extends metrics.py). Lead with ROC-AUC and F1 given real class imbalance on both targets, not accuracy.
7.2 The Barrier-Uplift Question — Unchanged Purpose, Same Priority
v1 Section 7.2's logic is the single most important carryover: train socioeconomic-only vs. socioeconomic+barrier-probability+cluster feature sets, and report the ROC-AUC delta per model per target. This remains the core empirical evidence for the paper's Stage 2 claim, and now runs on genuinely comparable individual-level data instead of a 707-row proxy version.
# src/evaluation/stage2_metrics.py (unchanged from v1)
def compute_barrier_uplift(model_fn, X_socioeconomic, X_full, y, target_name, cv):
from sklearn.model_selection import cross_val_score
auc_baseline = cross_val_score(model_fn(), X_socioeconomic, y, cv=cv, scoring='roc_auc').mean()
auc_full     = cross_val_score(model_fn(), X_full,          y, cv=cv, scoring='roc_auc').mean()
delta = auc_full - auc_baseline
print(f'{target_name}: socioeconomic-only={auc_baseline:.4f} | +barriers={auc_full:.4f} | uplift={delta:+.4f}')
return {'target': target_name, 'auc_socioeconomic_only': auc_baseline, 'auc_with_barriers': auc_full, 'uplift': delta}
7.3 Cross-Validation
With restricted-sample sizes still likely in the low hundred-thousands for both targets, single hold-out metrics are stable — 3-fold CV (matching Section 3.2's OOF fold count for consistency) as a stability check is sufficient; 5-fold is optional if compute allows.
